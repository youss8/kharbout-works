# Publish reproducible developer tools

Visitors need to inspect and rerun the behavior shown in the developer tools. The public workbench is a static Astro site, while some behavior depends on real Laravel requests and transactions or a Livewire runtime.

Publish Laravel and Livewire traces captured by executable tests with fictional data, and label the playback on the site. Wrap one Laravel approval operation in a standalone download with a locked dependency list and its tests. The approval writes its audit event and retry receipt in the same transaction as the state update. Each captured source reference points to a line from the archived implementation.

The workflow comparison runs baseline and candidate policies against explicit expected outcomes. The archive includes the same evaluator and a local runner. The CSV packs publish expected rows independently of their example importer. Both work with Node.js 24 without a hosted service.

The SQL worksheet runs an in-memory SQLite database in a dedicated browser worker. The worker bounds displayed output and can be terminated when a query runs too long. It is loaded when someone runs a query. The worksheet archive reproduces the sample using the SQLite module built into Node.js 24.

An alternative was to host shared writable examples for the public site. That would require hosting the PHP runtime, provisioning each visitor's data and resetting it between runs. Recorded server traces and runnable downloads keep the static hosting model while allowing developers to independently run and change the server examples.
