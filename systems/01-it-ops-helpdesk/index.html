Architectural approach

An internal IT operations console replacing spreadsheets with one system of record: an SLA-driven service desk, hardware asset & custody register, software-license seat tracker, and 12 config-driven operational registers (servers, printers, backups, phone lines, CCTV, mailboxes, remote-access IDs). A lightweight endpoint agent streams telemetry, raises threshold/availability alerts, and executes approved remote scripts, while an AI copilot and 11-tool OAuth MCP server operate under the exact same Postgres RLS permissions.

“Thick database, thin client” (business invariants at Postgres boundary so UI, agent API, copilot, and MCP tools behave identically); 4 RLS SQL helpers (is_staff, can_write, is_manager, is_super_admin) re-scoping ~30 policies atomically; pure unit-tested domain modules + thin *.db.ts adapters; 1 generic config-driven Register component powering 12 CRUD registers; explicit state machines (Tickets 6 states, Remote Commands 5, Runbooks 10 with allowed-transition map, Loans derived 5-state, Procedure Runs 4); expand–contract zero-downtime migration (account_id → branch_id); no soft deletes (explicit lifecycle flags + on delete set null).

Stack · Node.js 22 (CI-pinned), TypeScript 5.8 (strict, ESM), TanStack Start 1.168 (SSR, file-based routing, createServerFn RPC), Vite 8, Nitro, React 19.2, Tailwind CSS 4.2, shadcn/ui (Radix + cmdk), Sonner, TanStack Query 5, react-hook-form + Zod 4, Supabase PostgreSQL (RLS, PL/pgSQL triggers, pgcrypto, PostgREST), Supabase Auth + OAuth issuer for MCP, Anthropic SDK + provider-agnostic OpenAI-compatible/Gemini/Groq/Ollama fallback, 11-tool MCP server, PowerShell/Bash endpoint agent, ESLint 9, Prettier, Playwright + axe-core, CycloneDX SBOM + npm audit, full EN/AR RTL i18n (~1.8k-line dictionary).

Hardest data-modeling problems

1 · PostgreSQL backend architecture and immutable register history

Single polymorphic record_history table + one SECURITY DEFINER trigger diffs to_jsonb(NEW) vs to_jsonb(OLD) key-by-key, stores changed_fields[], before/after snapshots, and acting user while skipping no-op updated_at touches. attach_history('<table>') opts any table in; zero client write permissions.

2 · Cross-Cutting Funding Tag vs. Strict Physical Hierarchy

Branches host equipment funded by multiple Programs, so Region → Branch → Member stays a strict tree while Program is modeled as a cross-cutting tag rather than an impossible hierarchy parent.

3 · DB-Enforced Lifecycles, Atomic Command Claim & Deduped Alerts

  • Tickets: BEFORE trigger canonicalizes aliases (urgent→Critical), computes sla_due_at (4/8/24/48h), manages resolved_at with CHECK closed ⇔ resolved_at IS NOT NULL; comment trigger stamps first_response_at only on non-internal comments.
    • Equipment Loans: Trigger forces due_at and email flags to NULL for in-hours same-day loans, while overnight/off-site/after-hours loans derive due_at and require email record; partial index covers strictly the “needs chasing” set.
    • Remote Commands: Atomic FOR UPDATE SKIP LOCKED claim prevents concurrent agent check-ins from double-executing commands.
    • Alerts: Partial unique indexes guarantee max 1 open alert per (endpoint, rule) and 1 open availability alert per endpoint.

Enforcement layers

  • 100% RLS across all 47 tables
  • column-level GRANT restrictions
  • invite policy blocks super_admin invites
  • trigger overwrites created_by/author_id/technician_id with auth.uid()
  • SECURITY INVOKER dashboard RPC prevents queue-count leakage
  • SHA-256 agent token verifiers
  • strict body caps + per-token hashed rate limits
  • constant-time ≥32-char cron secret
  • DB length CHECKs (scripts ≤50k, output ≤100k)
  • 3-tier audit (record_history, operation_events, audit_log)
  • per-table safe selects that degrade the Copilot’s context when a source is unavailable.

Observed interface behavior

A ?ticket=<id> link opens an inline expanding row and relaxes filters that would hide the request. Selecting requests reveals bulk actions in the panel header. The frontend presents a message-based audit timeline. A visual before/after JSONB diff is a clean-room Vault enhancement marked [spec].

The Copilot is a full-page chat. Each table is selected independently under the current user’s permissions, so other sources remain available if one fails. An explicit data-sharing consent drawer is [spec]. The Hierarchy Explorer supports delete only. A retire-or-delete choice is [spec]. The Checklist Runner waits for request confirmation before marking an item complete.

Engineering highlights

  • Formula-safe CSV export quotes fields, neutralizes spreadsheet formula prefixes and emits a UTF-8 BOM for Arabic text.
  • The RFC-4180 importer normalizes header aliases and reports row-level problems before writing records.
  • Part-based bilingual formatters return {text, values} so translated messages control the order of numbers and units.
  • Arithmetic contrast tests measure foreground and background token pairs in both themes against WCAG AA thresholds.

Deployment and scope

No file attachments on tickets; routing is manual (filters + bulk assign) with resolution-based SLA + first-response tracking; no outbound email service beyond identity-provider auth emails (“email record” on loans is a tracked obligation flag); assets track cost/purchase/warranty without automated depreciation math.
